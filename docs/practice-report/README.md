## Робочий порядок

1. Використовувати `REPORT_PLAN.md` як узгоджений план документа.
2. Під час написання перевіряти факти за `CURRENT_STATE.md` і кодом.
3. Не описувати незавершені можливості як завершені.
4. Після оновлення застосунку повторно перевірити розділ 2.
5. Перед DOCX відрендерити Mermaid-схеми у SVG або PNG.
6. Сформувати автоматичний зміст, підписи та перехресні посилання у Word.
7. Перевірити підсумковий обсяг: не більше 20 сторінок.

## Межі паралельної роботи

Матеріали звіту зберігаються лише в `docs/practice-report/`. Під час паралельної розробки застосунку не змінювати файли `app/`, `content/`, `server/`, `shared/`, `tests/` і конфігурацію без окремого завдання.

## Наступні дії

- відрендерити рисунки 1.1 і 1.2;
- перевірити фактичний обсяг вступу та розділу 1 у тестовому DOCX;
- після завершення поточного етапу застосунку прочитати оновлений `CURRENT_STATE.md`;
- створити розділ 2 з фактичними результатами;
- сформувати висновки й остаточний список джерел;
- створити фінальний DOCX лише після погодження всіх розділів.
