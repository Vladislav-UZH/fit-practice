# ВСТУП

Сучасні інформаційні вебсистеми є важливим засобом подання структурованих відомостей про продукцію, технічні характеристики та напрями діяльності підприємств. На відміну від статичних вебсторінок, такі системи поєднують керування контентом, маршрутизацію, локалізацію, серверне формування сторінок, адаптивний інтерфейс і засоби перевірки якості програмного коду. Це дає змогу забезпечити послідовне подання інформації, зручний доступ із різних пристроїв і можливість подальшого розширення програмного продукту.

Актуальність теми практики визначається необхідністю застосування сучасних підходів до розробки інформаційних вебсистем. Компонентна архітектура, сувора типізація, серверний рендеринг, структурований контент і автоматизоване тестування дають змогу зменшити дублювання програмного коду, підвищити узгодженість даних і виявляти помилки до публікації змін. Серверне формування початкового HTML також є доцільним для інформаційних сторінок, зміст яких має бути доступним користувачу та пошуковим системам до завершення клієнтської гідратації [4].

Під час проходження проєктно-технологічної практики у період з 15 червня до 28 червня 2026 року виконувалося проєктування та розробка навчальної інформаційної вебсистеми для презентації продуктів ТОВ «МАКСІБУД». Робота проводилася на основі програмного проєкту, розміщеного в репозиторії `Vladislav-UZH/fit-practice`. Оформлення звіту здійснюється відповідно до погоджених вимог методичних рекомендацій Ужгородського національного університету [1], а структура викладу враховує загальні правила підготовки технічних звітів [2].

Вебсистема призначена для представлення концептуальної продуктової лінійки MAXIBUD ENERGY, до якої входять моделі MAXIBUD PowerBox 2400, MAXIBUD HomeCore 5 і MAXIBUD SiteHub 10. Продуктова лінійка та наведені характеристики створені для навчальної демонстрації програмного забезпечення. Вони не описують сертифіковане або перевірене комерційне обладнання. Розроблювана система не є інтернет-магазином, не містить функцій оплати чи оформлення замовлень і не призначена для виконання інженерних розрахунків, проєктування електричних систем або підтвердження сумісності обладнання.

Метою практики є проєктування та розробка інформаційної вебсистеми для структурованого представлення концептуальних продуктів ТОВ «МАКСІБУД» із застосуванням сучасних засобів веброзробки.

Для досягнення поставленої мети визначено такі завдання:

1. проаналізувати призначення вебсистеми, предметну область і межі проєкту;
2. сформувати функціональні та нефункціональні вимоги;
3. обґрунтувати вибір технологічного стеку;
4. спроєктувати архітектуру клієнтської, серверної та контентної частин;
5. налаштувати застосунок на базі Nuxt 4, Vue 3 і TypeScript;
6. реалізувати серверний рендеринг і API-маршрути Nitro;
7. створити структуровані українські та англійські записи продуктів;
8. застосувати Zod-схеми для перевірки даних і параметрів запитів;
9. реалізувати локалізовану маршрутизацію та метадані сторінок;
10. розробити адаптивний користувацький інтерфейс з урахуванням вимог доступності;
11. створити компонентні та наскрізні тести;
12. налаштувати автоматизовані перевірки за допомогою GitHub Actions;
13. проаналізувати отримані результати й визначити незавершені складові системи.

Об’єктом роботи є процес проєктування та розробки інформаційних вебсистем для представлення структурованих відомостей про продукти.

Предметом роботи є архітектурні, програмні та інтерфейсні рішення навчальної інформаційної вебсистеми для презентації концептуальної продуктової лінійки MAXIBUD ENERGY.

Під час виконання роботи використано методи аналізу вимог, структурного проєктування, компонентної декомпозиції, моделювання контенту, типізації даних, автоматизованого тестування та перевірки інтерфейсу на різних розмірах екрана. Технологічну основу проєкту становлять Nuxt 4, Vue 3, TypeScript, Nitro, Nuxt UI, Nuxt Content, Nuxt Image, Nuxt i18n, Zod, Vitest, Playwright і GitHub Actions.

Практичним результатом є цілісна двомовна інформаційна вебсистема, яка містить структуровані записи концептуальних продуктів, локалізовані маршрути, серверні засоби отримання даних, каталог, детальні сторінки продуктів, повне порівняння, інформаційні сторінки, демонстраційну контактну форму та автоматизовані перевірки якості. Система не розглядається як завершений комерційний продукт. До фінального рішення про готовність у межах погодженого обсягу залишаються остаточний статус візуальних матеріалів, ручний аудит доступності, формальні показники контрасту, LCP і CLS та завершення release-audit перевірок. Розгортання свідомо виключено з обсягу роботи.

Звіт складається зі вступу, двох розділів, висновків і списку використаних джерел. У першому розділі розглянуто призначення вебсистеми, вимоги, обмеження, вибір технологій та архітектуру. У другому розділі описано реалізацію програмного проєкту, локалізацію, користувацький інтерфейс, тестування, автоматизацію перевірок і фактичні результати розробки.

## Примітки до складання DOCX

Цей службовий підрозділ не переноситься до фінального тексту звіту.

- Орієнтовний обсяг після форматування: 1-1,5 сторінки.
- Заголовок `ВСТУП` починається з нової сторінки.
- Заплановані посилання: [1], [2], [4].
- Перед фінальним DOCX перевірити порядок джерел за першим згадуванням.
