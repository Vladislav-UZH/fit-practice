# ВИСНОВКИ

Під час проходження проєктно-технологічної практики було спроєктовано та розроблено двомовну інформаційну вебсистему для презентації концептуальної продуктової лінійки MAXIBUD ENERGY, пов’язаної в навчальному контексті з ТОВ «МАКСІБУД». Поставлену мету досягнуто: створено завершений для погодженого освітнього й демонстраційного обсягу Nuxt-застосунок із серверним рендерингом, структурованим контентом, локалізацією та автоматизованим контролем якості.

На етапі аналізу визначено призначення системи, категорії користувачів, функціональні та нефункціональні вимоги. Зафіксовано межі предметної області: вебсистема не є інтернет-магазином, не виконує інженерних розрахунків і не підтверджує сертифікацію чи сумісність обладнання. Такі обмеження дали змогу зосередити роботу на архітектурі, даних, інтерфейсі та перевірці програмного забезпечення.

Для реалізації використано Nuxt 4, Vue 3, TypeScript, Nitro, Nuxt Content, Nuxt i18n, Nuxt UI, Nuxt Image і Zod. Створено українські та англійські записи для трьох концептуальних продуктів. Спільні схеми перевіряють локаль, slug, структуру характеристик, порівняльні дані та контактні запити. Nitro API забезпечує отримання локалізованого списку продуктів, окремого запису та демонстраційне оброблення контактної форми.

Реалізовано головну сторінку, каталог, шість локалізованих детальних маршрутів, компактне й повне порівняння, контактну форму, сторінки Technology, About і Legal, а також контрольовану обробку помилкових маршрутів. Інтерфейс адаптовано до настільних і мобільних екранів. Власні SVG-візуалізації затверджено як остаточні для навчального проєкту.

Особливу увагу приділено доступності. Автоматизовані перевірки підтвердили семантичну структуру, наявність одного головного орієнтира й одного заголовка першого рівня, клавіатурний доступ, видимий фокус, reduced motion, доступні стани форми та відсутність горизонтального переповнення за ширини 320 CSS-пікселів. Формальні розрахунки контрасту пройшли встановлені пороги WCAG. Реальний screen-reader walkthrough залишається рекомендованим лише перед можливим публічним комерційним використанням.

Контроль якості автоматизовано за допомогою GitHub Actions. Фінальна послідовність включає детермінований release audit, ESLint, перевірку типів, 45 модульних і Nuxt runtime-тестів, production build та 33 Playwright E2E-тести. Synthetic LCP і CLS для репрезентативних маршрутів пройшли прийняті бюджети контрольованого CI-середовища.

У процесі роботи було виправлено дефекти валідації контенту, мобільного переповнення, гідратації контактної форми, локалізованих заголовків, фокусування помилок і запуску release audit у Windows. Це підтверджує практичну цінність поєднання типізації, автоматизованого тестування та браузерного аудиту.

Підсумкове рішення для застосунку сформульовано як `APPLICATION READY - DEPLOYMENT EXCLUDED`. Вебсистема готова для погодженої навчальної та демонстраційної мети. Розгортання, production persistence, реальна доставка контактних звернень і польовий моніторинг продуктивності свідомо не входили до завдання практики.

Отриманий результат демонструє застосування сучасного повного циклу веброзробки: від аналізу вимог і моделювання даних до створення інтерфейсу, серверної логіки, локалізації, тестів і фінального аудиту готовності.

## Примітки до складання DOCX

Цей службовий підрозділ не переноситься до фінального тексту звіту.

- Орієнтовний обсяг після форматування: 1 сторінка.
- Висновки починаються з нової сторінки.
- Нові факти, яких немає в розділах 1 і 2, не додаються.
